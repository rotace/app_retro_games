# 5. pure-graphics-dependencies

Date: 2026-07-14

## Status

Accepted

## Context

コア層（`retro_core`）は、プロジェクト憲法および [ADR0002](0002-workspace-structure.md) により、
ランナー層や OS/ウィンドウ系の具象（例: `minifb`、Framebuffer ioctl）へ依存してはならない。

一方で、角丸矩形・円・楕円・日本語テキストなどの描画をコア内で手書きし続けると、
ゲームロジックより描画ボイラープレートが増え、保守コストが上がる。

`embedded-graphics` や `u8g2-fonts` のようなクレートは:

- `no_std` 対応の純粋な描画／フォントユーティリティである
- ウィンドウや OS API を持たない
- 既存の `RenderTarget`（VRAM バッファ注入）に薄い `DrawTarget` アダプタで接続できる

そのため、「画面描画ライブラリ禁止」の意図（プラットフォーム具象の混入防止）とは衝突しない。

## Decision

コア層は次の依存を許可する。

1. **純粋描画クレート**（例: `embedded-graphics`）
   - 図形プリミティブと `DrawTarget` 抽象のみを利用する
   - OS / ウィンドウ / デバイスドライバには依存しないこと
2. **フォントデータ／レンダラ**
   - `u8g2-fonts` 等のクレート、または OFL 等のフリーフォントから
     必要文字だけをビットマップ化した埋め込みデータを利用する
   - セルフレジの日本語は丸ゴシック（M PLUS Rounded 1c）由来の
     埋め込みビットマップを使用（幼児向けの柔らかい見た目のため）
   - ランタイムでのネットワーク取得や動的フォント読み込みは行わない

接続方針:

- ランナー → コアの `RenderTarget` 注入モデルは維持する
- コア内で `RenderTarget` を `embedded-graphics::DrawTarget` に適合するアダプタを置く
- エラーは `Result` で扱い、欠落グリフなどでもパニックしない

禁止は継続する:

- `minifb`、ウィンドウマネージャ、OS 固有 ioctl などランナー責務のクレートをコアへ入れない

## Consequences

### Positive

- 角丸・円・楕円・テキスト描画の実装量が減り、ゲーム固有コードに集中できる
- 日本語表示を実績あるフォントセットへ置き換えられる
- プラットフォーム非依存のまま見た目品質を上げやすい

### Negative

- コアのバイナリサイズが増える（日本語フォントデータ分）
- 描画 API の知識がプロジェクト固有ヘルパから外部クレートへ移るため、学習コストがわずかに増える
